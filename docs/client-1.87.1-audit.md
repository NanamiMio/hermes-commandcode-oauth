没有升级客户端，也没有查询 npm 的远程 latest 标签。

## 已实现的改进

这些改动与本次限流、路由故障修复分开提交。

- 与客户端目录管理器一致，读取 `/provider/v1/models?view=client`。
  该响应包含 `minimumPlan`、`category`、`hidden`，以及别名、输入模态、上下文限制、
  输出限制、价格、推理强度和行为配置等信息。
- 对照客户端的 `createBilling`、`evaluateModelAccess`，结合 `/alpha/whoami`、
  `/alpha/billing/subscriptions` 和 `/alpha/billing/credits` 判断明确的套餐锁定。
  所有请求共享原来的目录查询超时预算。
- 读取当前响应里的 `whoami.org.id`，为账单及用量请求传入对应的 `orgId`；兼容旧的顶层字段。
- 与客户端一致处理套餐顺序及 `active`、`trialing`、`past_due` 订阅。
  `purchasedCredits`、`freeCredits` 可解除套餐锁定；`monthlyCredits` 不视为额外用量余额。
- 订阅查询失败、套餐未知或账单响应不完整时，不推断锁定。
- `fetch_models` 和兼容选择列表排除隐藏模型及已确认锁定的模型。
  `discover_models` 保留非隐藏模型，附带 `available` 和锁定说明 `note`。
  当前发行版 Hermes 的普通 provider 选择列表主要消费模型 ID，因此表现为隐藏锁定项；
  本次没有新增桌面端的锁图标。
- 成功但为空的目录与请求失败分别缓存。即使账号的全部模型都被锁定，也不会重新插入
  静态离线模型。缓存仍按 profile 目录、凭据指纹和 API origin 隔离。

## 仍值得改进的差异

1. **输入模态和模型别名。** 插件传输层仍依赖静态纯文本模型名单和别名；新客户端从丰富目录
   获取这些信息。后续应将按账号缓存的元数据传入客户端实例，同时保留未知模型的兼容行为。
2. **协议版本。** 插件仍发送 `0.52.1`，本地客户端版本为 `1.87.1`。
   本次没有直接改版本号：应先用对应版本的样例验证行为配置、工具/媒体格式及功能请求头，
   避免只声明版本却没有实现对应行为。
3. **流错误处理。** 新客户端的字符串错误读取器会丢弃顶层状态码，不能照搬。
   本次故障已证明，relay 的 `402` 不足以单独判定余额耗尽；插件保留明确 RPM 错误优先分类。
4. **套餐权限与瞬时限流。** `locked` 表示套餐权限，不代表 RPM 额度。
   当前可选模型仍可能限流，应由独立故障修复中的按模型冷却处理。

## 本地改动边界

故障修复由独立的插件和 Hermes 提交组成；账号目录改进是另外一个插件提交。
本次没有推送 GitHub 分支、创建 PR、合并仓库或更新远程目录 pin。
这些本地提交尚未替换正在运行的 Hermes 或已安装插件。
